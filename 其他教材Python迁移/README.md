## 二、从 notebook 到可运行脚本改了什么

原 notebook 是"边写边看结果"的交互式记录，直接拼成 .py 会有三类问题，本次逐一处理：

| 问题 | 原稿表现 | 处理方式 |
|------|----------|----------|
| Jupyter 专属语法 | `%matplotlib inline`、`get_ipython().magic(...)`、`display()` | 全部删除，改用 `matplotlib.use("Agg")` 后台绘图 + `savefig` |
| 隐式输出 | `df.head()`、`pca.explained_variance_ratio_` 单独一行，靠单元格回显 | 改为 `print()` / `to_string()` / 保存图片，脱离 Jupyter 也能看到结果 |
| 原稿 Bug | ARIMA 脚本引用未定义变量 `param_seasonal`；客户细分脚本的卡方检验写在 for 循环外（只检验了最后一对） | 修正逻辑并在注释中标注 |
| 依赖失传的第三方库 | `fa_kit`（因子分析，已停止维护）、`toad`（评分卡库，安装依赖重） | 用 `sklearn` 的 PCA / 手写 WOE-IV 等价实现，代码更透明 |
| 依赖本地环境 | 硬编码 Windows 路径；A 卡脚本末尾连本地 MySQL 做 Vintage 报表 | 路径改为相对 `data/`；MySQL 部分删除（需要数据库环境，不属于本案例核心） |

## 五、每个案例能学到什么

- **线性回归**：不是"跑个 OLS 就完事"，重点是共线性（VIF）、异方差（残差图）、正态性（Q-Q）、
  强影响点（Cook's D）四类诊断，以及为什么要取对数。
- **KMeans**：聚类前必须标准化；PCA 用于降维与去噪；轮廓系数用于选 k；
  聚类结果要用决策树翻译成业务规则，否则没人看得懂"簇 0/1/2"。
- **客户价值回归**：前向逐步回归用 AIC 控制变量数量；样本外打分要保证变量变换一致（取对数）。
- **ARIMA**：ACF/PACF 定阶 → 残差白噪声检验（DW、正态性）→ 预测；非平稳必须先 ADF 检验再差分。
- **评分卡**：IV 筛变量 → 分箱 → WOE 编码（把非线性关系线性化）→ 逻辑回归 → 刻度转换；
  分数分箱后坏账率必须单调，这是评分卡可用的前提。
- **多维细分**：先用卡方检验判断离散变量是否独立，再做正态化、降维、聚类、交叉画像。
